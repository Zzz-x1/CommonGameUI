## 1. 必做范围（建议）

| 模块 | V1 交付内容 | 范围边界 |
| --- | --- | --- |
| Node 与 Hierarchy | 默认 Root 及获取 API、实例身份、强类型父子引用、查询、单父归属、循环检查、自定义节点继承 | Root 已确认是结构性节点；不生成项目语义默认节点；暂不支持运行时跨父重挂载 |
| 生命周期 | 初始化、显示/隐藏、激活/失活、销毁及父子处理的明确协议 | 名称和精确状态表先设计；隐藏不等于销毁 |
| Container | 公共容器基础与独立显示容器，允许多实例并按实例关闭 | 独立显示容器名称待定；不把 Open/Push/Switch 全放公共基类 |
| Stack 容器 | PushAsync、出栈返回、当前项与历史维护 | V1 不做 Replace、指定目标/多层 Pop、持久化历史 |
| Tab 容器 | 内嵌项声明与绑定、SwitchAsync(string name)、可选泛型入口、当前项、切换后保留实例 | 项可为基础 Node，无需具体 View；名称在容器内定位，缺失/重复直接抛错；不重复加载或克隆 |
| 基础模态 | 弹窗叠加、遮罩、下层输入阻断、确认/取消结果、恢复焦点 | 承载容器类型及 ShowDialogAsync 的归属先确定；不要求业务继承 Modal |
| 异步协调 | 可等待操作、CancellationToken、容器内操作协调、作用域退出、重入规则 | 不提供遗失异常的内部 fire-and-forget，不隐式自动重试 |
| 注册与资源 | 手写类型注册、可替换工厂/加载接口、失败释放、根退出清理 | 不绑定具体 DI 或资源系统；无通用对象池与缓存预算 |
| 后端契约 | 创建、挂载、显隐、排序、输入/焦点、销毁、宿主线程调度 | 实际接口先由场景反推，不抽象全部控件 |
| 转场 | 可等待扩展接口，显式即时转场及一个简单动画示例 | 配置即时转场是正常配置，不是失败兜底；动画失败必须传播 |
| Source Generator | 模块注册入口与相应容器上的强类型便捷调用 | 不新增 Analyzer/诊断分析功能；保留手写入口，不按名称后缀识别 |
| 验证与交付 | 假后端、Godot 项目中的实际验证、相应适配器及运行示例、核心行为测试 | Godot 验证载体已确认，版本和 UI 后端待选；模板中的具体节点定义属于示例项目 |
| 异常和日志 | 原始异常与堆栈传播、上下文日志、异步失败可观察 | 禁止吞异常、保底、降级；双失败协议实现前确定 |

## 2. 可选项（不作为 V1 完成条件）

- 显式资源预加载与资源保留，不扩展成通用缓存框架。
- 第二个后端的最小验证适配器，用于尽早发现对第一引擎的隐式依赖。
- 后端子节点引用的基础代码生成，前提是不扩大生成器与配置系统范围。

不应因这些可选项延迟核心与第一个实际适配器的可用交付。

## 3. 延期范围

编辑器配置与可视化树、Analyzer 与诊断面板、完整绑定/MVVM 框架、通用组件系统、跨引擎控件/布局/样式体系、所有引擎的完整适配器、历史持久化、运行时重挂载、通用池化/LRU 缓存、复杂转场编排、多玩家独立输入、自动重试和故障降级。

自动重试和故障降级不能因未来版本扩展而默认启用，仍须遵守硬性异常约束。

## 4. 简化实现的默认规则建议

- 一个节点只属于一个父节点；父节点最终销毁时销毁子树。
- 栈内保留被覆盖实例以支持返回；出栈后销毁该实例。
- Tab 优先内嵌页面工作流（已确认偏好），V1 建议只实现已有页面绑定与切换。页面随父资源创建后绑定，不能再次克隆，切换后保留实例，按明确所有权清理；编辑器预览显隐不隐式决定运行时默认项。独立资源动态 Tab 延后考虑。
- 独立显示按实例定位；类型级单实例策略可后续增加，不与历史实例混用。
- 同容器并发请求明确抛错，不默默跳过；V1 可先不提供请求队列，但所有操作要可等待。
- 转场期间阻断该容器的相关交互；生命周期重入规则明确，不能死锁或隐式成功。
- 弹窗技术失败抛原异常，用户取消返回明确业务结果，调用取消传播取消状态。

这些均是建议；不可在未确定的状态表和失败协议下直接实现。失败时一致性清理不等于吞错或保底继续运行。

## 5. 实现前需先定下的内容

1. Node/Container 的公共成员，以及独立显示、Stack、Tab、模态能力的类型归属。
2. 生命周期、状态传播、父子销毁顺序与操作提交点。
3. 并发、取消和重入规则；主操作与清理同时失败的传播方式。
4. Godot 验证项目的目录、适配后端、目标版本与 C#/.NET/生成器编译工具链。
5. Tab 项和节点的声明方式，生成器最小输入契约。

## 6. V1 验收场景

项目自行创建节点并完成：栈式进入背包和详情、出栈返回；背包内切换装备/材料 Tab；打开两份独立详情并关闭指定实例；嵌套确认弹窗并恢复输入和焦点；销毁父节点结束子树任务与资源持有。

此外应验证：加载/生命周期/动画故意失败时日志和调用方能观察原始异常与堆栈；取消后没有迟到显示；不兼容操作在容器类型上不可调用；生成注册与手写注册复用相同核心流程；核心不依赖引擎程序集，假后端测试通过，实际适配器示例可运行。

Tab Demo 应包含没有具体业务 View 的基础 Node 页面，使用字符串名称切换；验证同类型不同项可定位，以及名称缺失/重复时抛错，不隐式选择其他项。

## 7. 开发阶段与完成标准

以下为建议顺序，未开始的工作不应标记完成。

| 阶段 | 工作内容 | 完成标准 | 状态 |
| --- | --- | --- | --- |
| 0. 契约确定 | 类型、生命周期、取消/并发、失败传播、首个后端与工具链 | 第 5 节问题形成明确设计；更新总设计文档 | 初版已实现 |
| 1. 节点基础 | 实例、父子层级、注册工厂、生命周期与日志 | 无引擎测试验证层级及父子退出，失败原样传播 | 初版已实现 |
| 2. 容器能力 | 独立显示、Stack、Tab、基础模态 | 相应类型直接暴露 API，组合场景可用 | 初版已实现 |
| 3. 异步与后端契约 | 资源所有权、取消、调度、转场、焦点与挂载 | 假后端覆盖加载/转场失败及退出清理，无迟到显示 | 初版已实现 |
| 4. 代码生成 | 注册入口及类型化调用 | 生成与手写入口共用核心逻辑，无 Analyzer 功能 | 初版已实现 |
| 5. 实际适配与交付 | 一个后端、项目模板、运行示例、使用说明 | 第 6 节核心场景及异常场景可验证，示例实际运行 | 初版已实现 |

阶段可以迭代交叉推进；首个实际适配器应尽早验证创建、挂载、线程调度和生成器兼容性，避免全部核心完成后才发现契约不适合宿主。

## 9. Godot Demo 设计

### 9.1 定位与维护原则

已确认：长期维护一个 Godot C# Demo，随框架功能持续迭代，兼作实际验证载体。初版已实现。

本节的场景、资源路径和业务名称为项目设计建议，不是框架默认节点。尚未定稿的容器名称、API 和配置声明，应在实现时替换为最终契约。

Demo 的目标是让开发者实际操作框架典型能力，并能找到对应业务代码。使用基础 UI 和必要动画即可，不以美术制作或完整游戏逻辑作为 V1 交付条件。不引入诊断面板来满足演示需要，基础日志使用宿主输出。

素材获取（已确认）：Demo 所需素材由开发时自行从网上获取，无需用户提供。优先选择可用于 Demo 展示并允许随项目分发的素材，保持图标、字体、窗口及按钮风格协调。获取时核验实际素材与许可，不凭搜索摘要推断使用权限；在项目中记录来源链接、作者、许可证及必要署名，并保留要求附带的许可文件。使用项目内本地素材，不依赖运行时外部图片链接。未获授权不采购付费素材。用户已选择候选④ Kenney UI Pack - Adventure 卡通冒险风格，现使用纸张面板、木框按钮、旗帜、滑块与选项控件素材，配合 Nunito 字体。原始 CC0/OFL 许可和来源记录位于 Assets，项目样式集中在 Themes/Adventure.tres。

### 9.2 入口与功能场景

建议一个入口场景提供以下按钮，每个功能场景独立建立和清理 Root 下的演示子树，方便重复验证。共享已初始化的框架与宿主服务，不要求为各演示建立多个上下文。

Root 验证：Demo 初始化框架后通过公开 API 获取默认 Root（例如候选 `ui.Root`），将项目定义的演示节点挂在其下。验证未配置时只有结构性 Root，不自动出现项目语义节点。同一框架实例重复获取应返回同一 Root；场景隔离可通过 Root 下的演示子树实现，不要求每个演示都创建新的框架上下文。多上下文仍为待定能力。

| 场景 | 操作 | 展示的框架能力 |
| --- | --- | --- |
| 内嵌 Tab | 点击画质、声音、控制标签 | 同资源基础 Node 项，字符串名称切换，状态保留 |
| 设置窗口导航 | 打开设置、进入画质页、返回、关闭窗口 | 模态外壳与内部 Stack 组合，遮罩和历史职责分离 |
| 背包组合 | 进入背包，切换内嵌装备/材料标签，进入详情后返回 | Stack 内嵌 Tab，不同容器能力组合 |
| 多实例 | 同时打开两份不同内容的详情，分别关闭 | 实例身份及精确关闭，不依赖类型猜测目标 |
| 模态结果 | 打开确认框，进一步打开嵌套确认框，确认/取消 | 结果返回、输入阻断、焦点恢复 |
| 生命周期与取消 | 在加载或转场中退出场景 | 子树清理、取消传播、无迟到显示 |
| 故意失败 | 单独运行缺失项、重复声明、加载/生命周期/转场失败用例 | 日志、原始异常和堆栈传播，禁止兜底 |

故意失败用例与正常演示入口分离。失败后停止该用例，不 Catch 后继续假装成功；测试夹具可以断言捕获到的原异常，但不能把吞错逻辑加入框架或正常业务流程。不同失败用例分别启动或隔离运行，不能为了让按钮继续工作隐藏失败。

### 9.3 内嵌 Tab：首个核心演示

建议资源 `Scenes/Tabs/EmbeddedTabsDemo.tscn` 在设计时包含所有页面：

```text
EmbeddedTabsDemo
├── TabButtons
│   ├── GraphicsButton
│   ├── AudioButton
│   └── ControlsButton
└── TabContent
    ├── GraphicsPage
    ├── AudioPage
    └── ControlsPage
```

逻辑结构：

```text
EmbeddedTabsDemoView
└── Tabs : TabContainerNode
    ├── Graphics : 基础 Node
    ├── Audio    : 基础 Node
    └── Controls : 基础 Node
```

三个项均不定义专门的 GraphicsView / AudioView / ControlsView 类。演示脚本在父资源创建后，通过项目声明的引用绑定页面；按钮调用 `tabs.SwitchAsync("Graphics")`、`tabs.SwitchAsync("Audio")` 等。绑定 API 待定，不为 Demo 伪造已经实现的生成声明。

明确初始项为 Graphics；设计时可将任意页显示以预览，但运行时仍以显式初始配置为准。每页放置一个可编辑控件（例如滑块或复选框），切换后返回应保留值。TabContent 是后端显示位置，Tabs 是逻辑节点，两者不按名称自动推断绑定。

验收：只有当前项正常显示并交互；切换不新增显示实例，不重复初始化；保留控件状态；未知名称与重复项名称直接抛错；父资源退出后逻辑节点、订阅和显示对象按所有权清理，不重复卸载内嵌资源。

### 9.4 设置窗口：模态外壳与内部栈

建议资源分别提供窗口外壳、设置首页、画质页。这里的画质页展示 Stack 历史，是上一节内嵌 Tab 演示之外的独立用例。

```text
SettingsWindow.tscn
├── Backdrop（半透明遮罩）
└── Window
    └── BodyMount

SettingsPage.tscn
├── GraphicsButton
└── CloseButton

GraphicsPage.tscn
├── QualityControl
└── BackButton
```

逻辑结构为 SettingsWindowView 下的 Body : StackContainerNode；SettingsView 和 GraphicsView 为 Body 管理的历史项。窗口模态能力的类型归属仍需先确定，不要求这两项继承特定 Modal 基类。

操作流程：打开窗口并进入设置首页；点击画质执行 Body.PushAsync；点击画质页返回执行 Body.PopAsync（出栈命名待定）；关闭设置首页则结束整个窗口。

验收：进入画质不新增第二层遮罩；设置首页被保留以支持返回；整个过程窗口外输入被阻断；最后关闭窗口后移除遮罩并恢复有效焦点。销毁窗口同时结束内部栈及未完成操作。

### 9.5 背包、独立实例与模态结果

- 背包资源内嵌装备和材料页，按名称切换；打开详情由外部 Stack 执行 Push，返回后保留背包标签与控件状态。
- 多实例用例同时显示两份不同物品详情，关闭第一份不得影响第二份，操作按实例定位。
- 模态结果用例区分确认、用户取消、调用取消及技术异常；嵌套弹窗关闭后焦点归还给前一个有效对象。

这些场景可以复用物品详情和确认框资源，但不能绕过框架 API 直接显隐以伪造框架能力。具体独立显示与弹窗 API 需跟随最终容器契约。
