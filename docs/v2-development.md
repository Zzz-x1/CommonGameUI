# V2 开发文档

更新日期：2026-10-02（Asia/Shanghai）。状态：开发计划，尚未开始实现。

设计依据：[唯一设计文档](design-decisions.md)，尤其第 6 节的现状审查与第 7 节的生命周期方案建议。V1 交付记录保留在 [V1 开发文档](v1-development.md)。本文集中维护 V2 范围、实施顺序、迁移与验收，不另建生命周期专题文档。

**用户已确认方向**：V2 主要补全生命周期相关能力；遵守同步/异步边界、Node 模型、原始异常传播及长期 Godot Demo 约定。设计有缺陷时优先提出重构方案，所有改动不考虑历史版本兼容，不建立兼容层或双轨行为。以下具体 API、行为和优先级是本次实施建议，不能当作已实现或全部已获用户确认。

## 1. 版本目标

业务能够明确处理：初始化一次、进入前准备、进入完成、退出前准备、退出完成、覆盖与返回、交互资格变化、父节点影响及最终清理。既支持继承 Node，也支持通过独立处理器组合业务逻辑。

保持直接容器调用：`PushAsync`、`PopAsync`、`SwitchAsync`、`OpenAsync`、`CloseAsync` 不增加 Navigation / Selection 中间对象。不同原因通过生命周期上下文表达，不把 Push/Pop 专用回调扩散到所有 Node。

V2 完成标准是这些能力拥有明确契约、核心行为测试、Godot 实际场景及迁移说明；仅增加回调声明不能算完成。

## 2. 当前缺口与必做范围（建议）

| 工作项 | 当前缺口 | V2 交付目标 |
| --- | --- | --- |
| 进入/退出完整阶段 | 只有转场前 OnEnterAsync/OnExitAsync | 进入前、进入完成、退出前、退出完成；前置可等待、完成通知同步 |
| 生命周期上下文 | 无法辨别首次进入、返回、覆盖、关闭 | 不可变上下文，明确操作原因、源/目标节点与所属容器；不传引擎对象 |
| 激活/失活 | 输入状态变化不通知业务 | 同步通知稳定的业务交互资格变化，与转场临时输入锁区别处理 |
| 有效可见变化 | 祖先隐藏直接应用显示状态 | 明确子树可见变化通知，隐藏/恢复不重复初始化或播放子节点进入动画 |
| 生命周期处理器 | 只能继承覆写 | 独立接口、同步注册/移除、确定执行顺序、订阅释放规则 |
| 操作提交点 | 节点进入早于容器历史/焦点提交 | 完成通知观察已提交状态；明确提交后回调失败的可观察结果 |
| 取消和重入 | 已有基础防护，新增回调尚无协议 | 覆盖所有新阶段；禁止成功通知伪造、重复清理或等待自身 |
| 销毁协议 | 直接 Dispose 不走 OnExitAsync | 明确正常关闭、强制销毁、部分初始化失败的差异及清理顺序 |
| 全容器接入 | Stack/Tab/Modal 状态路径各异 | Panel、Stack、Tab、Modal、Root/结构节点遵守同一生命周期规则 |
| Godot 与生成器迁移 | V1 接口已在 Demo 使用 | 按新契约调整适配器和生成调用，同步迁移业务示例，不保留历史兼容入口 |

核心 API 形态与通用定义只维护在设计文档第 7 节。V2 不以复刻 UnityScreenNavigator 的全部接口为目标，借鉴其阶段划分与处理器组合能力。

## 3. 实现前必须确定的契约

第一阶段先定下以下内容，并将选定方案更新到唯一设计文档，再编写内核：

1. `OnEnteringAsync/OnEntered/OnExitingAsync/OnExited` 的最终名称；是否增加初始化完成、销毁完成通知，以及它们确有必要的使用场景。
2. 上下文字段与原因集合，首次进入与再次显示是否分开表达；哪些信息必填、哪些阶段不存在源/目标。
3. 业务激活与 `IsInteractive` 的关系；转场临时输入锁不触发业务暂停/恢复的具体实现。
4. 完成通知的状态保证：Current、History、显隐、输入所有者、焦点、容器输入锁的提交顺序。
5. 多节点参与操作时回调顺序、子树传播顺序，以及回调中只读查询与重新操作的限制。
6. 处理器顺序、注册时机、重复注册、回调中增删，以及初始化/清理配对规则。
7. 提交前恢复和提交后失败的边界；强制销毁中同步通知失败后仍须继续哪些必要清理。
8. V1 覆写点的替换与工程内调用迁移清单，删除旧契约，不增加兼容调用路径。

建议直接明确这些默认行为，不把每一项做成可配置策略，避免 V2 出现过多接入参数。

## 4. 场景行为要求与验收

以下按设计文档建议方案制定，是实施验收目标；阶段 0 选择不同语义时须同步修改。

| 场景 | 应验证的生命周期行为 |
| --- | --- |
| 设置→画质→返回 | 设置只初始化一次；画质首次进入与设置返回可区分；完成回调能查询正确 Current；只保留一个遮罩 |
| Tab Graphics→Audio→Graphics | 基础 Node 仍可按字符串切换；处理器无需业务 View；返回原实例与控件值；每次显示有前/后阶段 |
| 背包进入详情再返回 | 覆盖不是销毁；背包及内嵌选中 Tab 的有效可见/激活变化正确，未选中 Tab 不收到激活 |
| 模态与嵌套模态 | 下层可见但失活；恢复时不重复进入/初始化；焦点恢复后回调观察稳定状态 |
| 独立窗口多实例 | 打开/关闭只影响目标实例的生命周期；其他实例不会因容器临时输入锁频繁暂停/恢复 |
| 父节点退出与恢复 | 后代按确定顺序收到有效变化，无重复通知；不重新播放每个后代的入场动画 |
| Root 或父节点强制销毁 | 不伪造正常退出；操作取消、失活、子树清理、资源释放顺序明确；每节点清理至多一次 |
| 初始化期间失败 | 不发初始化成功或进入完成；部分订阅和资源仍清理，主异常保持同一对象与堆栈 |
| 准备/转场失败或取消 | 未到提交点不发成功完成；恢复后的状态变化不得冒充成功操作 |
| 完成通知失败 | 操作任务失败，已提交状态可查询；不假装回滚，不自动重试，也不重播完成通知 |
| 生命周期内重入 | 同容器再操作、销毁当前操作拥有者、处理器回调中非法修改订阅直接抛错，不死锁 |
| 清理及附加失败 | 必要清理继续，首个原异常向上抛，额外原异常记录并可获取，不包装或丢弃 |

失败用例分别运行。测试夹具可断言预期异常；正常 Demo 不捕获技术异常后继续伪造成功。

## 5. Godot Demo 增量计划

继续维护现有 `Demo/Godot`，保留 Adventure 样式和已有入口，不新建替代 Demo 工程。

- 设置页显示“首次进入/返回”及进入次数，画质页在进入完成时更新提示，关闭验证清理。
- 内嵌 Tab 保持基础 Node，给页面挂独立生命周期处理器，演示无需创建空 View 类。
- 背包给选中页面增加一个轻量计数/定时更新示例，稳定激活时运行，覆盖/父隐藏/模态阻挡时暂停，恢复后继续。
- 嵌套模态演示下层“仍显示、已失活”和恢复焦点，不把失活等同销毁。
- 宿主输出使用普通日志记录阶段、原因和节点实例；场景用简短业务标签反馈，不引入专门诊断面板。
- 自测断言阶段顺序、次数、实例身份与当前容器状态；故意失败入口扩展到准备、完成通知、状态通知与清理失败。
- README 更新人工操作、预期日志、启动命令与实际验证结果；未运行的平台如实标注。

## 7. V1 迁移建议

- 初始化及最终清理继续使用原有职责；旧 OnEnterAsync/OnExitAsync 分别迁移为新的前置钩子。
- 按用户确认规范，一次迁移工程内 Demo、适配器、生成器及测试，删除被替代的旧钩子，不设置兼容过渡期、旧入口转发或双轨路径。
- 当前容器提交/状态传播设计若妨碍正确生命周期，应先重构职责与操作流程；不以追加回调或旧行为开关绕过问题。
- 生成器随新契约调整，继续满足容器直接调用的已确认方向；V2 不增加新的生命周期 Source Generator、Analyzer 或诊断模块。
- Godot AttachToAsync/BindAsync 仍需等待可异步初始化与失败清理；新增同步通知不意味着取消所有生命周期异步入口。

## 8. 延期与范围边界

不纳入 V2：第二引擎适配器、编辑器节点配置、动态 Tab、运行时重挂载、通用缓存/池化、MVVM/绑定系统、操作队列、复杂并行转场、跨会话历史、多玩家输入及诊断分析。生命周期处理器优先采用稳定顺序，不引入通用插件管线或依赖排序图。

资源后台加载与加载器改造不是本版目标。现有同步 Godot 加载器仍如实描述为同步，不为配合生命周期命名额外创建线程或空任务。
